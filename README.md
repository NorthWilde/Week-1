# Why Are We Here?
As a designer, I used to think of programming as something mainly for programmers. My job was to think about visual style, interaction, composition, and user experience, then programmers would turn those ideas into working products. However the development of AI coding tools has made this boundary less clear. Today, i can describe what i want in natural language and ask an AI to generate a piece of code within seconds. If machines can already write code for us, why should designers still learn programming?

After watching Dylan Beattie's The Art of Code, I began to think about programming differently. One of the ideas that stood out to me is that code is not simply a technical instruction for a computer. It can also be a creative medium. Beattie's presentation shows how programming can be used to create visual forms, patterns, animation, music, and other experiences. This made me realise that the relationship between design and programming is much closer than I had previously thought. Programming is not only about making software work; it can also be a way of expressing ideas.

For a designer, learning programming is therefore not necessarily about becoming a professional programmer. It is about learning another way of thinking. When I design an interface, animation, or interactive experience, I usually think about how it should look and how users should experience it. Programming makes me think about what happens behind the experience: What causes an interaction? What happens when a user does something unexpected? How can different elements respond to each other? These questions help turn a visual idea into a working system.

This is also why I do not think AI makes programming knowledge unnecessary. AI can generate code very quickly, but it does not automatically understand what I am trying to achieve as a designer. I can ask AI to create an interaction or an animation, and it may produce code that technically works. However, if I do not understand the basic logic behind the code, I may not know why something goes wrong or how to change it. I would be depending on a system that I cannot fully control.

I see AI more as a creative assistant than a replacement for programming knowledge. If I understand programming, I can use AI to speed up repetitive or technically difficult tasks while still making the important creative decisions myself. This is similar to using software such as Photoshop or Blender. I do not need to know how these programs were built, but understanding their tools and limitations gives me more creative control.

Programming can also help designers communicate with developers. In a multidisciplinary project, a designer might describe an interaction as “smooth,” “responsive,” or “playful,” while a developer needs to translate these ideas into specific behaviours and rules. Knowing some programming allows designers to understand what is technically possible and communicate their ideas more clearly.

My own experience with Digital Media Art has made me increasingly aware of this. I have worked with tools such as Unity, Unreal Engine, Blender, After Effects, and Figma. When working on interactive projects, I have realised that visual design alone is not enough. A game, interactive installation, or digital product is also a system of rules, behaviours, and relationships. Programming helps me understand these systems instead of only designing their appearance.

I do not think every designer needs to become a professional software engineer. In an AI-assisted future, it may be more important to understand how to break down a problem, ask the right questions, evaluate generated code, and modify it when necessary. AI can make programming more accessible, but this also makes understanding programming more valuable.

We are not learning programming because machines cannot write code. We are learning programming because machines can write code, and we need to understand, question, direct, and creatively use what they produce.
